# TrueFit 简旨 · 项目现状快照

## 一、一句话现状

**一个能跑通"上传简历+JD → AI瘦身 → 用户微调 → 导出"的 Web 产品**。
- 前端：`index_live.html`（单文件，1800+ 行）
- 后端：`server.py`（Flask，3 个接口）
- Pipeline：`src/pipeline/`（step1-6 + Gate）
- LLM：DeepSeek API

**还没上线，只在本地 `localhost:8000` 跑。**

---

## 二、产品定位（一句话）

**不编造、不美化，只把已有的经历，排到最该被看到的位置。**

核心约束：**每条 AI 输出必须绑定 source_ids + operation**，一切可溯源。

## 三、现在能做什么（功能清单）

### 首页

- ✅ 上传简历/JD：支持 `.txt` / `.md` / `.pdf` / `.docx` / 粘贴文本
- ✅ 配置抽屉：4 维度勾选 / 权重滑块 / 6 种预设（通用/技术/管理/校招/用户自定义/系统自动）
- ✅ 两个入口按钮
  - 主按钮（蓝）：**自己给简历瘦身** → 上传 → 编辑页
  - 次按钮（白）：**一键生成瘦身简历** → 上传 → 结果页（标记"自动聚类功能开发中"）

### 编辑页（从"自己瘦身"进）

- ✅ 卡片列表：显示 8 条经历（每 E 一张卡）
- ✅ 勾选保留 / 取消勾选
- ✅ 拖拽排序
- ✅ 拖拽合并（一卡拖到另一卡上）
- ✅ 勾选多段 → "合并到一组"
- ✅ 退出编辑 → "整理完成"

### 结果页

- ✅ 左栏：简历原文（从 source_store 渲染）
- ✅ 中栏：瘦身简历（三层：核心/相关/其他）
  - 从"一键生成"来：**按 tier 分三层大模块**
  - 从"自己瘦身"来：**单列按用户顺序**（tier 只作卡片标签）
- ✅ 悬停高亮（中栏句子 ↔ 左栏原文，双向）
- ✅ 点击跳转（中栏句子点击 → 左栏滚动定位）
- ✅ 底部匹配报告（可折叠）
  - 四维度分数
  - 命中项 / 缺口项
  - 改动说明（按 op 分组）
  - 补充建议
- ✅ 中栏行内编辑
  - "✎ 进一步编辑" → 逐句改字 → 改过的标 user_edited，脱离溯源
  - "↻ 还原"（每经历一个）→ 恢复 AI 原始处理
- ✅ 导出：Markdown / 纯文本 / 复制到剪切板
- ✅ "← 返回整理"（只有从编辑页来的才有）

### 后端

- ✅ `POST /api/upload`：接收简历+JD（文本或文件），启动后台任务，返回 job_id
- ✅ `GET /api/job/{job_id}`：轮询进度
- ✅ `GET /api/result/{job_id}`：拿最终产物
- ✅ 每次上传独立目录：`data/jobs/{job_id}/`（含 resume.json / jd.json / scored.json / clusters.json / changes.json / report.md / meta.json）
- ✅ PDF 解析（pypdf）/ Word 解析（python-docx）

### Pipeline（已跑通）

- ✅ step1 简历提炼（LLM，~6 秒）
- ✅ step2 JD 提炼（LLM，~4 秒）
- ✅ step3 四维度打分（规则 + bge-m3 embedding，~6 秒）
- ✅ step4 分层（规则，<1 秒）
- ✅ step5 改写指令生成（LLM，~60 秒 ← 最慢）
- ✅ stepG Gate 1-4 校验（规则）
- ✅ step6 匹配报告（规则）

**总耗时约 88 秒**（大头在 step5）。

## 四、关键决策记录（**为什么这么做**）

> 这一节最重要。看代码看不出来，必须记录下来。

### 4.1 只做减法，不新增事实

- **决策**：AI 只压缩/重组，绝不编造
- **落地**：Gate 1-4（source_ids 必须存在、公司名/时间/职位不能改、operation 白名单、数字/动词/事实名词必须在原文找到）
- **原因**：招聘市场简历造假是主要痛点，反向做"诚实瘦身"是差异化

### 4.2 双模式：一键生成 vs 自己瘦身

- **决策**：保留两个入口，且**主推"自己瘦身"**
- **原因**：
  - 自动聚类算法**还没写**（一期用"每 E 一个 G"占位）
  - "自己瘦身"是**功能完整**的路径
  - 用户自己组合能生成真正个性化的结果
- **一期妥协**："一键生成"按钮下加小灰字"自动聚类功能开发中"

### 4.3 编辑页去掉"删除"和"回收站"

- **原始设计**：卡片可 ✕ 删除，进"已删除区"，可恢复
- **改后**：只有"取消勾选"（保留在原列表，只是不进入最终简历）
- **原因**：
  - "取消勾选"和"删除"**功能重复**（结果页都不显示），用户困惑
  - 极简风：一个动作用一种方式
  - 用户想"清理视觉"是极低频操作，不值得为它引入一整套回收站逻辑

### 4.4 编辑页的"跨层排序"处理

- **问题**：结果页按 tier 分三层（核心/相关/其他）；用户把"其他"拖到最上面，结果页还是按 tier 分层，顺序被忽略
- **决策**：
  - **从"一键生成"来**：结果页保持三层
  - **从"自己瘦身"来**：结果页**单列，按用户顺序**（tier 只作卡片标签）
- **原因**：尊重用户的控制权——用户拖到最上面，就是要在最上面

### 4.5 step5 按"每 E 一个 G"生成，用户聚类只做前端拼接

- **背景**：自动聚类算法没有，但"自己瘦身"需要 step5 的产物（用户看到的是改写后的文本，不是原文）
- **决策**：
  - 上传后后端**自动构造"每 E 一个 G"的 clusters**，跑 step5，生成 8 条 change
  - 用户在编辑页聚类后，**前端把对应的 change 拼接**（多条 bullet 放同一卡片），**不调后端重跑**
- **原因**：
  - 省一次 LLM 调用（用户每改一次等 60 秒，体验太差）
  - 拼接 = "多条独立 bullet 放一起"，**每条 bullet 本来就是完整句子**，读起来自然

### 4.6 "返回整理"只在编辑模式显示

- **规则**：
  - 从"一键生成"进结果页 → **不显示**"← 返回整理"
  - 从"自己瘦身"进结果页 → **显示**"← 返回整理"
- **实现**：`state.cameFromEdit` 标记
- **原因**：一键生成没有"编辑状态"可返回

### 4.7 报告不反映用户编辑（一期妥协）

- **现状**：用户编辑页改了经历，报告还是后端的原始报告
- **原因**：
  - 报告是 step6 生成的（依赖 clusters）
  - 要反映用户编辑，需**重新调后端跑 step6**（60 秒延迟）
  - 一期先接受"不一致"
- **二期**：可能加"报告重新计算"按钮，或者前端简单过滤

### 4.8 编辑页的 UI 演进

- **从"左对齐标题 + 单行说明"** → **"居中标题 + 2×2 bullet 说明"**
- **原因**：标题作为"页面主题"需要视觉分量；单行说明太糊，2×2 bullet 更清晰

### 4.9 按钮主次对调

- **从**：主按钮 = "一键生成"，次按钮 = "自己瘦身"
- **改成**：主按钮 = "自己瘦身"，次按钮 = "一键生成"
- **原因**：主推功能完整的路径；一键生成标记"待开发"

## 五、技术债（**已知问题，以后要还**）

### 5.1 `EXPS` 的 key 用 `G_` 前缀，导致报告点击高亮失效

- **现状**：`finishEdit` 重建 `EXPS` 时，key 是 `G_G1` 这类
- **影响**：报告里"改动说明"点击条目 → 反查 gid → 找不到（因为原来的 key 是 `G1`）
- **修复方向**：key 命名统一；或者报告点击时兼容两种 key

### 5.2 报告不反映用户编辑

- 见 4.7

### 5.3 进度不持久化

- **现状**：90 秒里刷新页面，进度丢失，要重新上传
- **修复方向**：`job_id` 存 sessionStorage，页面加载时如果有就继续轮询

### 5.4 上传进度只有文案，没有百分比 / 取消

- **现状**：只有"正在分析简历…"这类文案 + spinner
- **修复方向**：加进度条（后端可返回"步骤百分比"）、加"取消任务"按钮

### 5.5 `step3` 对空数据无保护

- **现状**：如果 `jd.requirements.responsibilities` 为空，报 `'list' object has no attribute 'keys'`
- **已缓解**：`run_upload` 里加了前置检查（报友好错误）
- **修复方向**：`step3` 本身加保护，返回空结果而非报错

### 5.6 没有自动聚类

- 见 4.2

### 5.7 单文件 1800+ 行

- **现状**：`index_live.html` 巨大，改起来越来越累
- **修复方向**：React / Vue 重构
- **时机**：功能定型后再做

### 5.8 单机部署

- **现状**：只跑在本地 `localhost:8000`
- **修复方向**：前端静态托管 + 后端云服务器 + API key 环境变量

### 5.9 每次上传约花 0.05-0.1 元（DeepSeek API）

- **现状**：每次测试真花钱
- **修复方向**：
  - 上"限制次数"（如每用户每天 3 次）
  - 或切 Ollama 本地模型（第一次加载慢）
  - 或收费
