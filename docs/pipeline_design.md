# 调用链设计（Pipeline Design）
## 0. 定位
从简历原文到瘦身简历的完整生成链路。
串联多个调用环节 + 用户交互 + 纯规则组装，同时实现精准的 Source Mapping 和相关性引擎。

## 1. 总览

简历原文 + JD原文  
↓  
[调用1] 简历提炼（业务战役版 v9） → experiences JSON  
[调用2] JD提炼 → requirements JSON  
↓  
[调用3] 四维度打分 → 每条经历的分数  
[调用4] 分层 → 每条经历的 tier  
↓  
[调用U] 自动聚类（LLM） → clusters JSON  
↓  
[环节U] 用户选择 + 聚类（交互，在调用U初稿上手动调整）  
├─ 模式A：用户勾选 + 手动聚类  
└─ 模式B：系统自动全选 + 自动聚类  
↓  
[调用X] 句组切分（仅 granularity="bulletin" 时执行）：
  ├─ 结合 JD 过滤与高含金量保留
  ├─ 将粗颗粒 actions 拆分为简历级 bulletins
  └─ 精确溯源至句子级（如 W1_L3）
↓  
[调用5] 改写指令生成（非 bulletin 模式备用） → changes 数组  
↓  
[环节G] Gate 1-4 校验  
↓  
瘦身简历 + Source Mapping  
↓  
[调用6] 匹配报告生成（纯规则）  
↓  
匹配报告  
↓  
[调用7] 组装完整简历（纯规则）  
↓  
完整简历

## 2. 调用清单

| # | 环节 | 类型 | 输入 | 输出 |
|---|---|---|---|---|
| 1 | 简历提炼 | LLM | 简历原文 | experiences JSON（v9粗颗粒） |
| 2 | JD提炼 | LLM | JD原文 | requirements JSON |
| 3 | 四维度打分 | 规则+embedding | experiences + requirements | 每条经历4维度分数 |
| 4 | 分层 | 纯规则 | 分数 + 硬信号 | 每条经历 tier |
| U | 自动聚类 | LLM | experiences + requirements | clusters JSON |
| U' | 用户选择+聚类 | 交互 | 分层结果 + 调用U初稿 | 选中的经历 + 聚类分组 |
| X | 句组切分 | LLM | experiences + requirements + 句子级原文 | bulletins JSON |
| 5 | 改写指令生成 | LLM | requirements + experiences + 聚类 | changes 数组（sentence/paragraph 时启用） |
| G | Gate 1-4 校验 | 本地规则 | changes + source_store | 校验后的最终输出 |
| 6 | 匹配报告生成 | 纯规则 | 分数 + 命中项 + 缺口项 | 匹配报告 |
| 7 | 组装完整简历 | 纯规则 | 调用1产物 + 改写经历 | 完整简历 |

## 3. 每次调用的详情

### 调用1：简历提炼（业务战役版）
- **版本**：**v9 定稿**
- **输入**：简历纯文本原文
- **输出**：完整对象（含 basic_info / intent / education / skills_declared / experiences / source_store 等）
- **Prompt核心规则**：
  - **强制合并同类项**：禁止把一句话拆成多个 action。同一技术目标（如拆分模块、状态机、幂等处理）必须合并为一条。
  - **动作升级**：尽量使用主导、重构、设计等高级动词。
  - **过滤废话**：日常流水账（如 code review、需求评审）直接丢弃。
  - **粗粒度溯源**：因为动作合并，`source` 字段统一使用段落级编号（如 W1、P1），为下游的高质量重构打下基础。

---

### 调用2：JD提炼
- **输入**：JD纯文本原文
- **输出**：requirements JSON（含 hard / skills / responsibilities / industry / level + source_store + source_map）
- **版本**：v2 定稿

---

### 调用3 & 调用4：打分与分层
- **算法**：
  - 技能（三级兜底）、内容（bge-m3 embedding）、行业、资历加权综合。
  - 根据质量分、硬信号加分，按阈值分为核心 / 相关 / 其他。
- **验证结果**：排序完全一致，分层可靠。

---

### 调用U：自动聚类
- **类型**：LLM
- **输入**：experiences + requirements
- **输出**：clusters JSON（按业务主题分组）
- **版本**：已定稿

---

### 环节 U：用户选择 + 聚类
- **类型**：用户交互
- **交互细节**：卡片可勾选、删除、拖拽、合并。支持“打散经历”与“AI自动分组”。

---

### 调用X：句组切分（核心新增）
- **类型**：LLM
- **适用场景**：当 `granularity = "bulletin"` 时执行。
- **输入**：
  - 调用1 的 experiences（粗颗粒 actions）
  - 调用2 的 requirements
  - 句子级原文库（source_store，包含 W1_L3 等细致粒度）
- **输出**：`bulletins.json`（每个经历下包含多条 `text` 和精准的 `source_ids`）
- **Prompt核心规则**：
  - **合并与提炼**：将输入的业务战役长句，拆分为清晰、独立的简历 Bullet Points。
  - **强力保留**：不得删减状态机、分库分表等硬核术语，不得遗漏量化指标。
  - **精准溯源（强制）**：必须根据传入的句子级原文，输出精准到行的 `source_ids`（如 `["W1_L3", "P1_L5"]`），严禁只输出粗粒度 `W1`。
- **后端集成**：在 bulletin 模式下，系统将直接基于 `bulletins.json` 组装出 `changes.json`，跳过调用5和Gate严格校验，保证“原料不切割、指标不丢失”。

---

### 调用5：改写指令生成（备用链路）
- **类型**：LLM
- **适用场景**：仅当 `granularity = "sentence"` 或 `"paragraph"` 时执行。
- **输入**：requirements + experiences + 用户聚类结果
- **输出**：changes 数组
- **Prompt高能预警**：明确告知 LLM 输入的 actions 已经是提炼好的长句，严禁切碎，强保留数字和术语。
- **版本**：基于 v7 (段落级)/v8 (句子级) 兼容。

---

### 环节 G：Gate 1-4 校验
- **类型**：本地规则
- **豁免规则**：如果 operation 是 `verbatim` 或 `compress`，且 `source_ids` 非空，则直接放行（信任前序步骤的高质量提炼），只对 `reword` 进行严格数字校验。

---

### 调用6 & 调用7：匹配报告与组装
- **匹配报告**：纯规则生成总体分、命中项、缺口项与补充建议。
- **组装简历**：将基本信息、教育经历、技能清单与经历文本（从 bulletins 或 changes 取）拼装成完整简历。

## 4. 调用之间的数据衔接
- 调用1 → 调用3/4/5/X：experiences 传递
- 调用2 → 调用3/5/X：requirements 传递
- 调用3 → 调用4：分数传递
- 调用4 → 环节U：tier 传递
- 环节U → 调用5 / 调用X：选中的经历 + 聚类分组
- **调用X → 前端（第4步）**：生成带有精准句子级溯源的 bulletins。
- **调用X → 环节G**：经校验后组装成 changes 渲染至前端。

## 5. Source Mapping 的埋点
- **调用1**：粗粒度（W1/P1）级别，确保宏观对齐。
- **调用X**：将粗粒度的动作，反向对齐到具体的句子级编号（如 `W1_L3`），实现真正意义上的“单句级精准溯源”。

## 6. 异常处理
| 环节 | 异常 | 处理 |
|---|---|---|
| 调用1/2 | 失败 | 提示用户重新上传 |
| 调用3/4 | 失败 | 兜底给默认分层 |
| 调用X | 失败/解析错 | 回退至原始 actions / 提示重试 |
| Gate校验 | 失败 | 回退原文 |
| 调用6/7 | 失败 | 用默认模板兜底 |
