# 〇.问题（已解决，存档）

**1. 每个维度怎么算**
- 技能：JD要求的硬技能，经历里是否命中
- 内容：经历做的事，跟JD要求的职责是否像
- 行业：经历的行业，跟JD要求的行业是否匹配
- 资历：经历的角色层级，跟JD要求的层级是否匹配

**2. 分数怎么合成**
- 权重：技能20% / 内容45% / 行业15% / 资历10%
- 不归一化到0-100，保持0-10分制
- 阈值：核心≥7 / 相关4-7 / 其他<4

**3. 语义相似度用什么**
- 待定（实现阶段决定用本地模型或API）

**4. 安全规则怎么嵌进去**
- 已拆成两条修正规则：经历质量评估（降分）、硬信号升级（加分）
- 执行顺序：4维度打分 → 加权 → 质量调整 → 重算 → 硬信号加分 → 最终总分
- 详见第二章

# 二.算法设计及其合理性检验

本章包含三部分：
1. **相关性计算算法**（自研）—— 基础打分逻辑
2. **两条修正规则**（经历质量评估、硬信号升级）—— 对基础分的修正
3. **合理性检验方法** —— 用打分表验证算法

---

## 1. 相关性计算算法（自研）

### 1.1 打分维度

每条经历与JD的相关性，从4个维度打分（0-10）：

| 维度 | 说明 |
|---|---|
| 技能 | JD要求的硬技能，经历里是否命中 |
| 内容 | 经历做的事，跟JD要求的职责是否像（工作内容匹配） |
| 行业 | 经历的行业，跟JD要求的行业是否匹配 |
| 资历 | 经历的角色层级，跟JD要求的层级是否匹配 |

**默认权重：** 技能20% / 内容45% / 行业15% / 资历10%

**维度可配置：**
- 用户可勾选维度（取消勾选 = 权重置0）
- 权重可调（仅对已勾选项），自动归一化
- 提供预设系列（通用/技术/管理/校招）
- 调整后实时重算分层

**注：**

> 原“成果量化5%”和“教育背景5%”不作为独立维度。
> 
> - **成果量化**：已并入“经历质量评估”（metrics 计分），不单独设权重。
> - **教育背景**：属于“硬性条件”校验（学历门槛），不参与相关性打分。

### 1.2 打分参考标准（0-10）

| 分档 | 技能 | 内容 | 行业 | 资历 |
|---|---|---|---|---|
| 8-10 | JD核心技能直接命中 | 做的事几乎一样 | 同行业同场景 | 层级完全匹配 |
| 5-7 | 命中部分/相关技能 | 部分重叠 | 相关行业 | 层级接近 |
| 2-4 | 沾边 | 弱相关 | 弱相关 | 层级偏低/偏高 |
| 0-1 | 完全无关 | 完全无关 | 跨行业 | 差太远 |

### 1.3 阈值分层

| 分层 | 分数区间 | 说明 |
|---|---|---|
| 核心 | ≥7 | 最该被HR看到 |
| 相关 | 4-7 | 有相关性，但不突出 |
| 其他 | <4 | 无关或弱相关 |

### 1.4 特殊处理：行业维度中性化

**规则：**
- JD有行业要求：按标准打分（8-10 / 5-7 / 2-4 / 0-1）
- **JD无行业要求（required为null）：行业维度中性化，所有经历给默认中位分（5），不参与区分**

**理由：** JD没要求行业时，拿简历的行业去算匹配是“无中生有”。

---

## 2. 修正规则（两条）

### 2.0 算法执行顺序

```
4维度打分
  ↓
加权总分
  ↓
质量调整（调内容分）—— 2.1
  ↓
重算加权总分
  ↓
硬信号加分 —— 2.2
  ↓
最终总分
  ↓
分层（核心/相关/其他）
```

**顺序说明：** 质量调整必须在硬信号加分**之前**。否则加分会被质量调整“吃掉”（因为质量调整会降低内容分，进而降低总分，把刚加的硬信号分抵消）。

---

### 2.1 经历质量评估（降分）

**目的：** 压低“边角料经历”的分数，避免它们因方向沾边而被高估。

**计算方式：** 从现有字段推导，不新增字段。

| 信号 | 判断 | 分值 |
|---|---|---|
| role | 独立负责/主导 → 3；参与/协助 → 2；实习/兼职 → 1；边角料 → 0 | 0-3 |
| actions 数量 | ≥4 → 3；2-3 → 2；1 → 1 | 0-3 |
| 有量化 | metrics 非空 → 2 | 0-2 |
| 有定性结果 | results 非空且 metrics 为空 → 1 | 0-2 |

**质量分 = 加总，0-10**

**应用：调整内容分**

```
调整后内容分 = 原内容分 × (0.5 + 质量分/20)
```

| 质量分 | 系数 | 效果 |
|---|---|---|
| 10 | 1.0 | 不降 |
| 8 | 0.9 | 降10% |
| 5 | 0.75 | 降25% |
| 3 | 0.65 | 降35% |
| 0 | 0.5 | 降50% |

**作用范围：** 只影响内容分，不影响技能、行业、资历。

**设计原则：**
- results 和 metrics 不重复计分（有量化时只算 metrics）
- 低质量经历被压低，高质量经历不受影响
- 只降分，不加分

---

### 2.2 硬信号升级（加分）

**目的：** 抬高命中JD“具体硬信号”的经历，避免被加权分低估。

**硬信号定义：**
> JD里具体且非泛化的要求，满足以下任一：
> - 出现 ≥2 次（反复强调）
> - 被独立列为职责或技能（不是混在长句里）

**说明：** 两个条件（出现≥2次 / 被独立列出）满足任一即可。
- 同时满足 → 强硬信号（如JD3的“支付系统对接”）
- 只满足“独立列出” → 弱硬信号（如JD4的“PRD撰写”）
- 两类都算硬信号，加分规则相同

**提取方式：** 从JD的 skills + responsibilities 里筛选。

**升级规则：**
1. 经历的 actions/tech 命中任意硬信号 → 总分 +1.5
2. 命中多项 → 累加，上限 +3

**上限说明：** 命中多个硬信号时，累加但不超过+3。
- 命中1个 → +1.5
- 命中2个 → +3
- 命中3个及以上 → 仍 +3

**作用范围：** 总分，不影响单个维度分。

**设计原则：**
- 只加分，不降分（降分交给质量评估）
- 泛化要求（Java、MySQL）不算硬信号

---

### 2.3 两条规则的关系

| 规则 | 方向 | 作用对象 | 解决的问题 |
|---|---|---|---|

| 硬信号升级 | 加分 | 总分 | 硬信号命中被低估 |

**互不干扰，可同时应用。**
