# TrueFit 简旨 · 产品设计文档

> 本文档基于高保真交互原型 `prototype/index.html`（单文件 HTML/CSS/JS）整理，描述产品「TrueFit 简旨 —— 简历智能瘦身」的页面结构、交互逻辑、状态规则与视觉规范。
> 原型为**桌面端单页应用（SPA）**，设计基准宽度 1440px，最小宽度 1180px，未做移动端适配。

---

## 一、产品概述

### 1.1 产品定位

TrueFit 简旨是一款**面向求职者的「定向简历」生成工具**：用户上传一份完整简历和目标岗位 JD（职位描述），系统按岗位要求对简历进行"瘦身"——保留事实、按相关度重新分层组织、压缩冗余、省略无关内容——输出一份可以直接投递的**瘦身简历**，并附带一份解释"为什么这么改"的**匹配报告**。

一句话概括：**按目标岗位，给简历瘦身。**

### 1.2 核心价值

| 痛点 | 产品对策 |
|---|---|
| 同一份简历海投，与岗位匹配度低 | 以 JD 为标尺逐段评估经历相关度，定向重组 |
| 手动改简历耗时、不知取舍 | AI 自动完成分层、压缩、合并、省略，并给出每条改动的理由 |
| 担心 AI 改简历"编经历" | 最高原则：**保留全部事实，不虚构经历**；每句瘦身文本都可溯源到原文 |
| AI 改完不放心、不可控 | 三栏对照（原文 / 瘦身 / 报告）+ 人工编辑模式 + 双向溯源高亮 |
| 不同岗位看重的维度不同 | 打分维度权重可配置，提供技术/管理/校招等预设 |

### 1.3 设计原则

1. **事实零虚构**：瘦身只允许对原文做保留、压缩、改写、合并、调序、降级、省略七类操作，不允许新增原文没有的数字、技能、职责。
2. **一切可溯源**：中栏每一句瘦身文本都携带 source 映射（对应左栏原文的一个或多个片段 ID），悬停/点击即可双向对照。
3. **人始终有最终决定权**：AI 给初版，用户可以继续编辑文字、拖拽排序、导出；但人工编辑不回写原文、不触发报告重算。
4. **状态不丢失**：上传内容与配置实时持久化到 sessionStorage，从结果页返回首页无需重新上传。

## 二、目标用户与典型场景

### 2.1 目标用户

- 以**技术岗求职者**为首要对象（预设系列、示例数据均以后端开发岗为例），同时兼顾管理岗、校招等场景。
- 用户特征：有一份内容完整但冗长的简历（原型示例为 5 年经验、8 段经历），需要针对具体岗位快速产出定制版本。

### 2.2 核心使用场景

1. **定向投递**：拿到某岗位 JD → 上传简历 + JD →（可选调整权重）→ 一键生成 → 核查报告 → 微调 → 导出投递。
2. **多岗位复用**：投完 A 岗位后返回首页，替换 JD、调整预设，再次生成 B 岗位版本；简历文本保留在首页不丢失。
3. **事实核查**：HR 视角逐条核对瘦身简历——每句话能不能在原文找到出处？AI 有没有夸大或杜撰？
4. **学习改写思路**：通过右侧"改动说明 + 补充建议"理解自己简历与岗位的差距（如缺 Go、缺大模型经历、资历偏高等）。

## 三、产品结构总览

### 3.1 站点地图

```
TrueFit 简旨（SPA）
├── 视图1：首页 #view-home
│   ├── 顶栏（Logo + 「进入瘦身配置」入口）
│   ├── Hero 标题区
│   ├── 上传区（简历卡片 ｜ JD 卡片，各占一等宽）
│   ├── 生成按钮区（四态主按钮 + 状态提示）
│   └── 瘦身配置抽屉（右侧滑出，覆盖于首页之上）
└── 视图2：结果页 #view-result
    ├── 顶栏（Logo + 「← 返回首页」）
    ├── 匹配提示横幅（岗位名 + 改写原则）
    └── 三栏工作区（1 : 2 : 1）
        ├── 左栏：简历原文（只读，可收起为 46px 竖条）
        ├── 中栏：瘦身简历（预览态 / 编辑态，可导出）
        └── 右栏：匹配报告（可收起为 46px 竖条）
```

全局浮层：生成中 Loading 遮罩、轻提示 Toast、按钮悬浮气泡 Tooltip。

### 3.2 导航方式

- 两个视图通过 CSS 类 `active` 切换显隐（同一页面内切换，无浏览器跳转、无刷新）。
- 首页 → 结果页：点击生成按钮（生成成功后自动切换）。
- 结果页 → 首页：点击右上角「← 返回首页」。

## 四、页面一：首页

首页承担"采集输入 + 配置参数 + 触发生成"三件事。

### 4.1 顶栏

- 左侧：品牌标识「**TrueFit 简旨**」（TrueFit 为品牌蓝色）+ 灰色小字「简历智能瘦身 · 原型」。
- 右侧：**「⚙ 进入瘦身配置」**按钮（浅蓝底蓝字），点击从右侧滑出配置抽屉；抽屉打开时按钮反色变为「✕ 收起配置」。

### 4.2 Hero 区

居中标题「**按目标岗位，给简历瘦身**」，副标题「上传完整简历、目标 JD，调整配置，完成简历瘦身。」

### 4.3 上传区：简历卡片 / JD 卡片

两张卡片等宽并排（间距 28px，最大总宽 1040px），结构完全对称：左为「📄 简历 Resume」，右为「🎯 岗位 JD」。卡片为固定高度 **480px** 的白色圆角面板，内容区独立滚动，避免上传长文本后把页面撑高。

**(1) 卡片头部**

- 标题 + 状态标签：未上传时为灰色「未上传」；上传成功后变为绿色「已上传」。
- 右侧「上传文件 / 粘贴文本」分段切换 Tab。

**(2) 上传文件模式**

- 虚线拖拽区（Dropzone）：点击调起文件选择器，也支持把文件直接拖入（拖拽悬停时边框变蓝、底色变浅蓝）。
- 说明文案：支持 PDF / Word / Markdown / TXT（原型中仅 TXT/MD 可直接读取文本，其余为产品形态占位）。
- 卡片底部：「载入示例简历 / 载入示例 JD」次级按钮，一键填入内置的示例文本（张伟·后端 5 年简历 + 后端开发工程师-AI Agent 的 JD），便于演示与试用。

**(3) 粘贴文本模式**

- 工具条：提示语 +「📋 粘贴剪切板」按钮（调用浏览器剪切板 API；被浏览器拒绝时提示用户手动 Ctrl+V）。
- 大文本框：支持粘贴全文，输入即实时写入状态。

**(4) 已加载状态**

上传或粘贴完成后，卡片内部切换为已加载面板：

- 顶部：类型图标、文件名（或"粘贴文本"）、字符数、右上角「✎ 编辑」按钮。
- 中部：带滚动条的**文本预览框**（白底、等宽展示全文）。
- 底部操作：「重新选择」「清空」两个文字链接。
- **上传文本可再编辑**：点「✎ 编辑」后预览框变为可编辑状态（contenteditable，淡黄底蓝边），按钮变「✓ 完成修改」；锁定时若内容与原始上传文本不同，预览框标记淡黄底并显示绿色提示「✓ 文本已修改（与原始上传内容不同）」。修改后的文本即作为后续生成的真实输入。

### 4.4 生成按钮区

两张卡片下方居中放置主操作区：

- **主按钮「一键生成瘦身简历」**：高 50px、最小宽度 240px、16px 字号、品牌蓝实心、带蓝色投影，是全页视觉重心。
- 按钮下方一行灰色状态提示（`gen-hint`），未上传完时显示琥珀色警告文字「请先上传完整的 Resume 和 JD」。
- 按钮上方悬停气泡（Tooltip）解释当前点击行为。按钮的完整四态规则见[第六章](#六生成按钮四态状态机)。

## 五、瘦身配置抽屉

从屏幕右侧滑入的 360px 宽抽屉，回答"按什么标准给简历打分、瘦身"的问题。抽屉不离开首页上下文，左侧页面仍可见。

### 5.1 打分维度区

四个维度，每个维度一行：

| 维度 | 含义 |
|---|---|
| 技能 | 简历技能栈与 JD 技能要求的命中程度 |
| 内容 | 经历中的职责/动作与 JD 岗位职责的命中程度 |
| 行业 | 经历所在行业与 JD 行业要求的相关程度 |
| 资历 | 经历资历档位与 JD 年限/级别要求的匹配程度 |

每行结构：

- 上方：勾选框 + 维度名 + 右侧实时百分比（该维度权重占所有已勾选维度权重之和的比例）。
- 下方：0–100 的滑块 + 数字输入框（联动），可精确调权。
- 取消勾选的维度整行置灰，滑块与数字框禁用；重新勾选后恢复。

### 5.2 预设系列区

2 列按钮网格，共 6 个预设：

| 预设 | 技能 / 内容 / 行业 / 资历 | 说明 |
|---|---|---|
| 系统自动判断 | 按 JD 智能匹配 | 原型逻辑：分析 JD 后静默落到最接近的固定预设（示例 JD 为后端技术岗 → 技术预设） |
| 通用 | 20 / 45 / 15 / 10 | 默认预设，内容权重最高 |
| 技术 | 30 / 30 / 10 / 30 | 技能与资历并重 |
| 管理 | 20 / 35 / 10 / 35 | 偏重资历与内容 |
| 校招 | 30 / 30 / 5 / 5 | 弱化行业与资历 |
| 用户自定义 | 自由调整分数 | 继承当前分数，允许自由编辑 |

交互规则：

- 选中固定预设时，四个维度自动重置为对应分值且**滑块/数字框锁定不可编辑**；点「用户自定义」后解锁。
- **任何对维度的勾选/取消、滑杆/数字修改都会立即把预设切换为「用户自定义」**——即用户一旦动手调参，就脱离固定预设。
- 仅打开抽屉不做任何操作，不算调参，不影响生成状态。

### 5.3 说明与抽屉内生成入口

- 灰色注释块用一句话解释调参规则（见上）。
- 抽屉底部吸底放置通栏「生成瘦身简历」按钮 + 状态提示行，其可用状态与首页主按钮**完全同步**；点击后自动收起抽屉并执行生成。

## 六、生成按钮四态状态机

主按钮是全产品唯一的生成入口，其名称、样式、可点性、点击行为、悬停提示由统一的状态判定函数管理，共四种状态：

| 状态 | 触发条件 | 按钮名称 | 样式 | 点击行为 | 悬停提示 |
|---|---|---|---|---|---|
| incomplete | 简历、JD 未全部上传 | 一键生成瘦身简历 | 灰色禁用 | 不可点 | 无；下方提示「请先上传完整的 Resume 和 JD」 |
| fresh | 已上传，从未生成 | 一键生成瘦身简历 | 品牌蓝实心主按钮 | 执行生成 | 按当前配置生成瘦身简历 |
| view | 已生成，且生成后输入无变化 | **查看已瘦身的简历** | 白底蓝字蓝边（次色样式） | **直接跳回结果页，不重新生成** | 回到结果页查看 |
| changed | 已生成，但生成后输入发生变化 | 一键生成瘦身简历 | 品牌蓝实心主按钮 | 按新输入重新生成 | 按新配置重新生成 |

补充规则：

- "输入变化"包含三类：**简历文本变了、JD 文本变了、配置变了**（维度勾选或权重）。
- 实现方式：每次生成成功时对 `{权重, 勾选, 简历文本, JD文本}` 拍快照（snapshot）；当前状态重新序列化后与快照比对，不一致即 changed。
- 两个按钮名称均为 8 个汉字，按钮固定 `min-width:240px`，状态切换时**宽度不抖动**。
- 重新生成会退出编辑模式并重新渲染三栏内容。

## 七、生成过程

点击生成（fresh / changed 态）后：

1. 全屏显示半透明 Loading 遮罩 + 旋转 spinner，文案「正在按当前简历、JD 与配置生成瘦身简历…」。
2. 原型以 750ms 延时模拟 AI 生成（实际产品由后端生成服务返回结果）。
3. 成功后：写入生成标记、刷新输入快照、退出编辑模式、渲染三栏、自动切换到结果页，按钮转为 view 态。

## 八、页面二：结果页（三栏工作区）

结果页是产品的核心工作台，设计目标是让用户在一个屏幕内完成"**看瘦身结果 → 对照原文核查 → 读报告理解 → 人工微调 → 导出**"的完整闭环。

### 8.1 顶栏与横幅

- 顶栏：左侧品牌标识，右侧「**← 返回首页**」文字按钮。
- 横幅（淡黄底警示色）：「当前匹配：**{岗位名}**｜改写原则：保留全部事实，不虚构经历」。岗位名取 JD 文本首个非空行（无 JD 时回落到默认示例岗位名「后端开发工程师（AI Agent）」）。

### 8.2 三栏布局

- 三栏宽度比 **左 1 : 中 2 : 右 1**，同处一个可伸缩容器，各栏为独立白色圆角卡片并**各自独立纵向滚动**（栏头 sticky 吸顶）。
- 中栏字号（15px / 1.5 行高）略大于左右栏（13px / 1.65 行高），视觉上突出最终产物；左右栏底色偏灰（#F9FAFB）以退居参照位。
- 左栏、右栏均可收起为 46px 窄条（见[第十二章](#十二左右栏收起--展开)），把空间让给中栏。

## 九、左栏：简历原文

**定位：只读的"事实底稿"，用于对照溯源，任何操作都不会修改它。**

- 栏头：「📄 简历原文」+ 灰色副标「只读・原始简历素材，用于对照溯源」+「收起原文」按钮。
- 内容按简历原生结构分组展示：
  1. 姓名与基本信息（性别/年龄/城市/学历/年限/联系方式）+ 求职意向；
  2. 教育经历；
  3. 技能清单（硬技能、软技能分行）；
  4. 工作经历一/二/三（公司行 + 逐条工作描述）；
  5. 实习经历；
  6. 项目经历（每个项目含项目名、背景、职责、技术方案、主要工作、结果）。
- 每一个原文片段都带有唯一 ID（如 `W1_L3`、`P1_L3`，对应数据层 source_store 的句子级切片），是中栏溯源高亮的锚点。
- 片段默认普通灰字；被联动高亮时变为品牌蓝浅底深字。

## 十、中栏：瘦身简历

**定位：AI 生成的最终产物，支持预览、溯源、编辑、排序、导出。**

### 10.1 三层分区（分层结果）

瘦身简历按相关度把经历组织为三个自上而下的分区，分区标题**水平居中、18px、带字间距**，样式刻意弱化"卡片感"：

| 分区 | 文案样式 | 含义（分层阈值） |
|---|---|---|
| 核心内容 | 黑色、加粗 | 与 JD 高度相关（相关分 ≥ 7），放在最前，先让 HR 看到最强证据 |
| 相关内容 | 黑色、常规字重 | 中度相关（4 ≤ 相关分 < 7），保留但压缩 |
| 其他内容 | 灰色、常规字重 | 弱相关/无关（相关分 < 4），极简保留或一句带过 |

每个分区标题右侧用小灰字标注「N 条经历」。被整体省略（omit）的经历不出现（如示例中的市场实习 E5）。

### 10.2 经历卡片

每个可见经历为一张白色描边卡片：

- **标题行**：经历名（如"订单中心重构"）+ 分层小胶囊（核心蓝、相关浅蓝、其他灰）+ **相关分徽章**。
- **相关分徽章**：胶囊形，文字「相关分 8.6」，悬停 title 提示"相关分 X/10，颜色越深代表与目标 JD 越相关"。
  - 核心/相关分区：底色在极浅蓝 `#eef2fe` → 品牌深蓝 `#4349b8` 之间按分数线性插值，分数越高蓝越深；文字颜色根据底色亮度自动在黑/白间切换以保证可读。
  - 其他分区：统一使用**浅灰底 `#f1f1f4` + 深灰字 `#6b7280`**，与上方蓝色体系明确区分，表示"这些内容不参与岗位相关度叙事"。
- **元信息行**：经历时间（灰色小字）。
- **句子列表**：该经历瘦身后的若干条 bullet，每条以小圆点引导。

### 10.3 句子与七类改写操作（Source Mapping）

每一句瘦身文本都带两类隐形数据：

- `src`：来源映射，指向 1 个或多个原文片段 ID（如一句合并句可同时对应 `W1_L3` + `P1_L5`）；
- `op`：本句使用的改写操作。

预览态下，鼠标悬停句子时：句子底色变浅蓝，右侧浮现操作标签。七类操作为：

| 操作 | 中文标签 | 含义 | 标签色 |
|---|---|---|---|
| verbatim | 保留原文 | 高价值句子原文照搬，未做修改 | 灰蓝 |
| compress | 压缩 | 删除低相关细节，保留核心信息 | 蓝 |
| reword | 改写 | 同义改写、表达专业化 | 紫 |
| merge | 合并 | 多条动作合并为一句，保留全部量化指标 | 青绿 |
| reorder | 前置 | 调整段落/句子顺序，前置高相关内容 | 靛蓝 |
| demote | 降级 | 从核心内容降级到相关/其他内容 | 琥珀 |
| omit | 省略 | 与岗位完全无关，整体省略不展示 | 红 |

> 设计意图：用户看到的不是一个"黑盒改写结果"，而是每句话都能回答"它从原文哪里来、AI 对它做了什么"。

### 10.4 预览态 → 编辑态

栏头右侧有「⬇ 导出」菜单和「✎ 进一步编辑」按钮。点击编辑后进入编辑态：

- 中栏外轮廓变为**蓝色虚线框**，栏头标题切换为「✏️ 瘦身简历」，副标提示「修改仅作用于瘦身简历，不会改动左侧原文、右侧匹配报告」；按钮变绿色「✓ 编辑完成」。
- 顶部出现蓝色提示条：「点击任意文字即可改写；拖动模块卡片可调整顺序；已修改句子标记 user_edited。」
- **行内改文字**：每个句子变为可输入（contenteditable），点击即可改写。
  - 内容与 AI 原文不同：句首圆点变绿，句尾常驻绿色标签「user_edited」，修改存入编辑状态；该句**同时解除 source 映射**（人工改写内容不再参与自动溯源，避免错误联动）。
  - 改回原文：自动撤销 edited 标记并恢复映射。
- **拖拽排序**：按住经历卡片可拖动调整顺序（基于 SortableJS，带半透明占位、旋转归零、180ms 动画），松开即生效。
- 点「✓ 编辑完成」退出并锁定为预览态，顶部弹出 Toast「已保存修改，瘦身简历已锁定预览」。
- 防丢失：编辑态下若存在未保存修改就关闭/刷新页面，浏览器弹出离开确认。

### 10.5 导出

「⬇ 导出」下拉菜单提供两种格式，按当前三层分区结构组织（包含用户的文字修改）：

- **导出 Markdown**（`瘦身简历.md`）：`## 核心内容` / `### 经历名（时间）` / `- 句子`。
- **导出纯文本**（`瘦身简历.txt`）：同级缩进的纯文本版本。

文件通过浏览器本地 Blob 下载，无需后端。

## 十一、右栏：匹配报告

**定位：解释 AI 的判断与改动，并给出投递建议。报告基于「AI 初始瘦身版本」，人工编辑瘦身简历后报告不会自动更新（栏头副标分两行明确告知这一时效性）。**

栏头结构经过专门设计：第一行放「📊 匹配报告」标题与「收起报告」按钮，第二行整行显示两行副标，避免按钮把副标文字挤成多行：

> 匹配分析基于 AI 初始瘦身版本
> 人工编辑瘦身简历后，报告不会自动更新

### 11.1 总体匹配

- 大号总分「**67** / 100」（品牌蓝），旁边一段结论性文字，示例：后端硬技能与核心职责命中度高；行业（AI/大模型）与资历（JD 要求 1-3 年）存在明显缺口，建议按补充建议微调后投递。
- 四维度进度条：技能 8.2、内容 7.6（蓝色填充）；行业 2.2、资历 4.2（琥珀色填充，表示短板），条形长度对应分值占比。

### 11.2 命中项（绿色区块）

标题「✅ 命中项（JD 要求 → 简历证据）」，逐条列出 JD 要求与简历中的支撑证据，例如：

- Java/Go：命中 Java —— E1 Spring Boot/MyBatis、E3 Spring Cloud；
- 系统优化/线上排查：E1 P99 800ms→300ms、E2 回调问题 15 起→2-3 起/月。

每条为"**要求项：证据描述**"结构，绿点引导，回答"我哪里匹配"。

### 11.3 缺口项（琥珀色区块）

标题「⚠️ 缺口项（JD 要求但简历未体现）」，琥珀点引导，回答"我哪里不够"，例如：

- Agent/大模型应用（bonus）：无智能体调度、工具调用、记忆、对话链路相关经历；
- Go：仅体现 Java 技术栈；
- AI/大模型行业：经历集中在电商/SaaS/制造业；
- 大厂经历（优先）：未体现；
- 资历 1-3 年：实际 5 年、最近两段为高级岗，存在资历偏高风险。

命中项与缺口项区块之间留白加大、行距放宽，保证长文本可读性。

### 11.4 改动说明

独立白色卡片，逐条解释 AI 对每段经历做了什么。每条 = **彩色中文操作标签 + 粗体经历名 + 说明文字**，例如：

- 🔼前置（reorder）：E1 订单中心重构，相关度 8.6，前置到核心内容首位；
- 🔗合并（merge）：状态机、幂等、模块拆分三条动作合并为一句，保留全部量化指标；
- ✅原文保留（verbatim）：15→2-3 起/月、对账半天→15 分钟为高价值量化结果；
- ✂️精简压缩（compress）：删除交接运维等低相关细节；
- 📉降低权重（demote）：相关度 3.7，CRUD 为主，压缩为一句放入其他内容；
- ⏭️省略（omit）：E5 市场实习相关度 0.8，整体省略（同时提示其行业是 JD 偏好的教育，可参考建议）。

每个操作标签**悬停显示黑色气泡**，解释该操作的定义（如"merge：多条动作合并为一句，保留全部量化指标"）。

### 11.5 补充建议

带编号圆点的有序列表，给出可执行的补强方向，例如：

1. 补充 AI Agent/大模型应用经历（智能体调度、工具调用、向量数据库、LLM 对接，个人项目也建议列出）；
2. 若有 Go、云原生、Linux 部署排障经验，显式声明并补经历证据；
3. 教育行业实习虽是市场岗，但教育是 JD 偏好行业，可用一行带过，不必整段删除；
4. 资历高于要求（5 年 vs 1-3 年），建议弱化年限、突出技术深度，避免 overqualified。

## 十二、三栏联动与收起机制

### 12.1 双向溯源联动

三栏之间通过原文片段 ID 建立联动：

- **悬停中栏句子（预览态）**：该句与左栏对应的所有原文片段同时高亮（蓝底），移出取消。
- **点击中栏句子**：左栏自动滚动，使第一个来源片段在栏内垂直居中并闪烁强调；实现"这句话出自原文哪里"的一键定位。
- **悬停/点击左栏原文片段**：中栏所有引用了该片段的句子高亮；点击时中栏滚动定位到第一条。
- **点击右栏改动说明条目**：同时高亮左栏相关原文 + 中栏整段经历卡片，并把中栏滚动到该经历位置。
- 人工编辑过（user_edited）的句子不参与上述联动，因为它已脱离 source 映射；编辑模式下点击一律视为文字编辑，不触发跳转。

### 12.2 收起 / 展开（左右对称）

- 左栏「收起原文」、右栏「收起报告」点击后，对应栏收缩为 **46px 宽的竖条**，正文与标题隐藏，仅保留一个**竖排文字按钮**（文字竖排、字间距 2px，带边框）。
- 左右两栏的收起/展开交互、视觉完全对称；竖条状态下按钮始终可见可点，点击即恢复原宽，空间自动让给中栏。

## 十三、核心用户流程

### 流程 A：首次生成（主路径）

```
首页上传简历（文件/粘贴/示例）
  → 上传 JD
  → 按钮从灰色禁用变为蓝色「一键生成瘦身简历」
  →（可选）打开配置抽屉：选预设或自定义权重
  → 点击生成 → Loading 750ms
  → 进入结果页：阅读横幅与总分
  → 中栏浏览分层结果，悬停句子查看操作标签
  → 点击句子核对左栏原文出处
  → 阅读右栏命中项/缺口项/改动说明/补充建议
  →（可选）进入编辑模式改文字、拖顺序
  → 导出 Markdown / 纯文本
```

### 流程 B：返回首页与重新生成

```
结果页点「← 返回首页」
  → 简历、JD、配置均保留（sessionStorage），无需重传
  → 按钮显示白底蓝字「查看已瘦身的简历」（view 态）
  → 分支1：未改任何输入 → 点击直接回结果页，不重新生成
  → 分支2：换了 JD / 改了简历 / 调了配置
     → 按钮变回蓝色「一键生成瘦身简历」（changed 态）
     → 点击按新输入重新生成，覆盖旧结果
```

### 流程 C：事实核查（HR 视角）

```
左栏读原文 → 看中栏瘦身句 → 双向悬停/点击核对出处
→ 检查操作标签：数字是否保留？动词是否被升级？是否出现原文没有的技能？
→ 查看 omit/demote 的内容是否删得合理
→ 结合右栏补充建议决定是否手动补回
```

## 十四、状态与数据模型

### 14.1 前端运行状态（state）

| 字段 | 内容 |
|---|---|
| `resume` / `jd` | `{name 文件名, text 文本}`，任一为空视为未上传 |
| `scores` | 四维度当前权重 `{skill, content, industry, level}`（0-100） |
| `checked` | 四维度勾选状态 |
| `preset` | 当前预设：auto 落到具体预设 / general / tech / manage / campus / custom |
| `generated` | 是否已成功生成过 |
| `snapshot` | 上次生成成功时 `{scores, checked, resume.text, jd.text}` 的序列化快照 |
| `order` / `deleted` | 经历的展示顺序与被省略（可恢复）列表 |
| `edits` | 用户人工改写内容：`{句子id: 新文本}` |
| `editing` | 中栏是否处于编辑模式 |
| `drawerOpen` | 配置抽屉是否打开 |

### 14.2 三类 Mock 业务数据

1. **SRC（原文片段库 / source_store）**：按 `W1_L1…W4_L7`（工作/实习）与 `P1_L1…P3_L5`（项目）编号的句子级原文切片，左栏与溯源联动都基于它。
2. **EXPS（经历元数据）**：每段经历的 `title / time / tier（core/related/other）/ score（相关分）/ role / cardActions`。
3. **BLOCKS（瘦身句块）**：每段经历瘦身后的句子数组，每句含 `id`、`op`（七类操作之一）、`src`（来源片段 ID 数组）、`text`（最终展示文本）；被省略的经历为空数组。

### 14.3 sessionStorage 持久化

- 存储键：`tf-home`；保存字段：resume、jd、scores、checked、preset、generated、snapshot。
- 任何会改变状态的操作（上传、粘贴、编辑文本、清空、调权、勾选、生成完成）都会触发一次保存；刷新页面或从结果页返回时自动恢复上传卡片、抽屉配置与生成按钮状态。

## 十五、打分与分层的产品口径

- **四维度打分**：技能、内容、行业、资历各为 0-10 分，按配置权重加权得总分；权重可由预设或用户自定义决定。
- **分层阈值**：加权（并经过质量分调整、硬信号加分等处理）后，**≥7 核心内容 / 4–7 相关内容 / <4 其他内容**，直接决定中栏分区与徽章颜色。
- **技能识别的兜底口径**（产品规则，算法侧已验证）：优先取经历显式技术栈；不足时从经历描述中补抽；仍不足且该经历确属技术岗时，用简历级技能清单兜底；非技术岗经历（如市场实习）不做技能兜底，避免技能分失真。
- **硬信号**：命中 JD 关键职责（示例为"AI Agent 后端开发"）给予加分；示例简历无此类经历，因此报告中该项未触发。
- 原型中的具体分数（67 分、8.6/7.4/6.3/3.7/0.8 等）为 Mock 展示数据；算法实现与验证由项目 `Test-scoring/` 下的打分脚本承担，与原型展示口径保持一致。

## 十六、视觉设计规范

### 16.1 风格定位

Linear / Notion 式的现代效率工具风格：大面积浅灰底、白色圆角卡片、克制的描边与投影、品牌蓝作为唯一主色。

### 16.2 色彩

| 用途 | 色值 |
|---|---|
| 品牌主色（按钮/链接/聚焦） | `#5e6ad2`，悬停 `#4f5cc0`，浅底 `#eef0fc` |
| 主文本 / 次文本 / 弱文本 | `#1f2329` / `#4b5563` / `#8a8f98` |
| 描边 / 页面底色 / 卡片底 | `#e5e7eb` / `#f6f6f8` / `#ffffff` |
| 成功（命中、已保存） | 绿 `#16a34a` + 浅绿底 `#e8f7ee` |
| 警告（缺口、提示） | 琥珀 `#b45309` + 浅琥珀底 `#fdf3e3` |
| 危险（省略、删除） | 红 `#dc2626` + 浅红底 `#fdeaea` |
| 分层色 | 核心=品牌蓝、相关=靛蓝浅系、其他=灰 `#8a8f98` |

### 16.3 字体、圆角、阴影

- 字体栈：-apple-system / PingFang SC / Microsoft YaHei 等系统无衬线字体；基准 14px / 1.6 行高。
- 圆角：卡片 14px、按钮/输入框 6-12px、胶囊标签 20px。
- 阴影：普通卡片极轻投影；浮层（抽屉、导出菜单、拖拽卡片）使用大柔焦投影；主按钮带品牌色发光投影。
- 交互反馈统一 0.12–0.26s 过渡；按钮悬停轻微上浮（translateY -1px）。

### 16.4 信息密度原则

- 最终产物（中栏）字号最大、留白最多；参照信息（左右栏）字号更小、底色更灰。
- 报告长文本区块加大行距并用虚线分隔条目；操作类标签全部彩色编码，支持扫读。

## 十七、异常与边界处理

| 场景 | 处理 |
|---|---|
| 简历/JD 未传完 | 生成按钮禁用 + 琥珀色文字提示缺输入 |
| 浏览器拒绝读取剪切板 | 文本框聚焦并提示手动 Ctrl+V |
| 仅打开抽屉未操作 | 不算配置变更，不触发 changed 态 |
| 固定预设下尝试改权重 | 滑块/数字框禁用；先切「用户自定义」才可编辑 |
| 人工编辑后溯源 | 编辑句解除 source 映射，不参与高亮联动，标记 user_edited |
| 人工编辑后看报告 | 报告不重算，栏头副标明确声明"基于 AI 初始版本" |
| 编辑中刷新/关闭页面 | beforeunload 弹出离开确认 |
| 输入权重越界 | 数字框钳制在 0–100 |
| 被 omit 的经历 | 不渲染于中栏，但在数据层保留于 deleted 列表，为"恢复已删经历"能力预留 |

## 十八、原型边界与后续规划

### 18.1 原型当前边界（Mock 部分）

- 文件上传仅 TXT/MD 可在浏览器本地读取；PDF/Word 的解析为形态占位。
- 生成过程为前端延时模拟，未接真实 AI 生成服务；报告分数与文案为内置 Mock 数据。
- 桌面端专用（viewport 固定 1440、最小宽度 1180），无移动端适配。
- 无账号体系、无历史版本管理（仅 sessionStorage 保存当前一次会话）。

### 18.2 可预见的产品化方向

1. 接入真实文件解析（PDF/Word）与简历结构化抽取服务。
2. 接入打分与瘦身生成服务：四维度打分、三级技能兜底、质量分调整、硬信号加分、Source Mapping 及四道内容门禁（白名单/黑名单/可解析/原文匹配，违规改写自动回退原文）。
3. 报告随人工编辑提供"重新分析"或差异提示，而不是完全静态。
4. 被省略经历的可视化恢复（从 deleted 区拖回）、多岗位版本管理与投递记录。
5. 生成结果的在线分享/链接，以及更多导出格式（PDF、DOCX）。
